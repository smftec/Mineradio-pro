# Mineradio pro

参考 [Mineradio](https://github.com/oirge/Mineradio) 全新开发的 Windows 本地音乐播放器。纯本地播放,不上传任何数据,在原版能力基础上新增**软件检测与自动更新**。

## 功能

- **曲库管理**:导入文件夹/文件,自动扫描元数据(标题/艺术家/专辑/流派/年代/时长),`chokidar` 监控文件夹变化自动同步,无需重启
- **智能分类**:艺术家 / 专辑 / 流派 / 年代 / 最近添加 / 最近播放 / 播放最多;全局搜索(Ctrl+K)
- **播放引擎**:MP3 / FLAC / WAV / OGG / Opus / M4A / AAC / WebM / AIFF;播放队列(队列视图管理)、随机、单曲/列表循环;0~10s 交叉淡入淡出;断点续播(重启后恢复上次队列与进度);损坏文件自动跳过
- **十段均衡器**:31Hz~16kHz,预增益,平直/流行/摇滚/古典/低音增强/高音增强预设,内置限幅器
- **歌词**:同名外置 `.lrc`/`.txt` + 内嵌歌词标签(USLT/Vorbis);**逐字歌词**增强 LRC 高亮;多编码自动识别(UTF-8/16、GB18030、Big5、Shift_JIS)
- **歌词视图**:主窗口全屏歌词,逐字渐变高亮、跟随滚动、点击行跳转
- **桌面歌词**:独立透明置顶窗口,双行显示、可拖动/锁定(鼠标穿透,设置页可解锁)/调字号/换颜色
- **迷你播放器**:独立小窗,封面+控制+进度,可置顶,位置记忆
- **播放统计**:播放次数/累计时长/完整播放/最近播放,记录可清空
- **音频输出设备**:可切换系统输出设备(`setSinkId`)
- **通用**:开机自启开关
- **⭐ 软件检测与更新**(新增能力):
  - 启动 10 秒后静默检查(可在设置关闭)
  - 设置页手动"检查更新" → 新版本提示(版本号+更新日志)→ 下载进度条 → "重启并安装"
  - 更新源默认 GitHub Releases,支持设置中填自定义 URL(可指向 OSS/CDN/国内镜像)

## 开发

要求 Node.js 22.12+(建议 24)。

```bash
npm install            # 若 Electron 二进制下载慢:
                       #   set ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
npm start              # 开发运行
npm run icon           # 重新生成应用图标(build/icon.ico)
npm run build:win      # 打包 NSIS 安装包 → dist/
```

开发辅助(仅 dev 生效):

- `MPRO_DEBUG=1` — 开启 CDP 调试端口 9222(`scripts/cdp-eval.mjs` 可驱动 UI)
- `MPRO_IMPORT=<文件夹>` — 启动后自动导入并播放,便于自动化验证

## 打包产物与发布(自动更新)

```
dist/
├── Mineradio-pro-1.1.0-Setup.exe   # NSIS 安装包(x64)
├── latest.yml                      # electron-updater 版本元数据(发布时必须上传)
└── Mineradio-pro-1.1.0-Setup.exe.blockmap  # 增量更新(发布时建议上传)
```

**发布新版流程:**

1. 把 `package.json` → `build.publish` 中的占位改为自己的仓库:
   ```json
   "publish": { "provider": "github", "owner": "你的GitHub用户名", "repo": "Mineradio-pro" }
   ```
2. 提升 `package.json` 的 `version`(如 `1.1.1`)
3. `npm run build:win`
4. 在 GitHub 仓库创建 Release:tag 为 `v1.1.1`,上传 `dist/` 下的 `Setup.exe`、`latest.yml`、`.blockmap`
5. 已安装用户的应用会在启动后自动检测到新版本 → 下载 → 重启安装完成升级

**不用 GitHub 的更新源:** 在应用「设置 → 软件更新 → 自定义更新源」填入任意 HTTP 目录地址(该目录下放置 `latest.yml` 与安装包),例如 OSS/CDN 镜像。留空则使用默认 GitHub Releases。「查看发布页」按钮自动读取打包配置中的仓库地址。

## 目录结构

```
├── desktop/               # 主进程(ESM)
│   ├── bootstrap.cjs      #   CJS 入口:privileged scheme 注册 + dev 开关
│   ├── main.js            #   生命周期/启动编排
│   ├── preload.cjs        #   contextBridge 安全桥
│   └── lib/
│       ├── store.js       #   JSON 持久化(设置/曲库/歌单/统计)
│       ├── protocol.js    #   mpro:// 本地音频/图片流(Range + 路径白名单)
│       ├── library.js     #   曲库扫描 + chokidar 监控
│       ├── metadata.js    #   music-metadata 标签/封面缓存
│       ├── lyrics.js      #   LRC/逐字歌词解析 + 多编码识别
│       ├── playlists.js   #   歌单 CRUD
│       ├── stats.js       #   播放统计/断点续播
│       ├── updater.js     #   electron-updater 封装
│       ├── windows.js     #   主窗/迷你/桌面歌词窗口
│       └── ipc.js         #   IPC 路由
├── public/                # 渲染进程(原生 ES Modules,无构建步骤)
│   ├── index.html / mini.html / lyrics.html
│   ├── css/  js/
├── build/                 # 打包资源(icon.ico)
├── scripts/               # 图标生成 / CDP 测试脚本
└── dist/                  # 打包产物
```

## 已知限制(计划后续版本)

- APE / DSD(dsf)解码需要自定义解码器,暂不支持
- 全局鼠标侧键热键(原版 uiohook-napi 原生模块)暂未集成
- Folia 视觉视图(唱片墙/拼贴墙/17 种歌词效果)暂未集成
- 项目路径建议放在本地 NTFS 盘;网络/虚拟盘上 Windows 沙箱进程无法运行 Electron
